# Execução e validação

Antes de editar, trace entrada, transformação, estado, saída e fallback do fluxo afetado. Para
conteúdo remoto, confira tipos, consulta GROQ, provider, fallback e apresentação. Para interface,
inclua teclado, foco, semântica, contraste e `prefers-reduced-motion` nos critérios relevantes.

Implemente a menor solução completa, seguindo o estilo existente. Não introduza `any`, estado
derivado, efeitos implícitos, memoização, lazy loading ou dependência sem benefício demonstrável.

Valide com `$validate-portfolio`. Compare o resultado aos critérios da spec e registre evidência
real. Se a implementação divergir do desenho, atualize o artefato com o motivo; não reescreva a spec
para esconder escopo incompleto.
